## 建议的用户验收

1. 运行安装包，选择希望安装的磁盘；若已有 BiliSum 正在运行，先正常退出旧实例再测试新版本。
2. 在首页“开始总结”右侧下拉菜单的“定时设置”中选择几分钟后的时间，点击该行“开始”，确认时间到达前不会进行下载或转写。此设置仅本次生效；外侧“开始总结”立即执行。定时执行要求应用 / Docker 服务在运行，休眠或关机期间不会唤醒系统。
3. 创建自定义 Prompt 并保存，回首页选择该预设后生成。
4. 用错误的 LLM Key 处理一次，确认转写保留且出现续跑按钮；更新 Key 保存后，仅重跑 LLM。
5. 在浏览器打开 Web 端，进入知识笔记的导出菜单，下载 Markdown；带图片的笔记应下载 ZIP，解压后图片引用完整。
6. 如要迁移已有大量数据，先查看迁移预览和所选目录，等新位置启动验证通过后再决定是否清理旧副本。

外部付费 LLM、真实 ASR / GPU 安装、Docker 容器和用户生产数据迁移未做完整验收。本地模拟网关的成功不代表某个外部网关已通过实测。

## R3 迁移修复与补充实测

此次由用户的真实截图复现并修复了以下问题：

- 扫描会进入 `cache_dir/runtime-temp` 下的 pip / uv 安装临时目录，遇到 EPERM 阻塞。现在只排除这一个由应用创建的临时子树，预览和实际复制采用相同排除规则；模型缓存、数据库和任务数据仍严格检查，不忽略任意权限错误，不修改生产目录权限。旧临时文件保留。
- 旧版 `briefvid/data` 内的 cache / tasks / out 是正常嵌套配置。现在生成唯一物理复制计划，上级目录与子目录不重复复制、不重复计数；子目录显示“空间已计入上级目录”。
- 未勾选的导出目录即使嵌套在数据目录内，也不会被复制或列入旧文件清理。设置、JSON 和数据库路径采用最长前缀匹配，并以原路径映射保护未迁移子目录。相同路径却选择相反的目录仍会阻止迁移，避免共享数据误清理。
- 长路径、错误详情和卡片最小宽度造成页面横向溢出。现在路径可换行、卡片随可用宽度排列，完整权限错误在“查看目录详情”中展开，拦截原因使用简短列表。
- 迁移停机时，React 定时刷新会替换设置页；正式打包主进程还会切回启动画面，导致进度和正在等待的 IPC 调用丢失。迁移期间暂停常规刷新并作废旧请求，保留设置页；主进程在受控迁移期间保留当前页面。完成或恢复后重新刷新。复制进度通知限频，避免大量小文件刷满界面。
